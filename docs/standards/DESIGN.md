# Miniapp Design Standard

本标准约束仓库内现在与未来的全部 miniapp。它定义共同审美判断，不要求项目共享一套外观。

## 核心判断

1. 主题先于装饰。视觉、文字、声音、动效、组件和交互必须帮助用户进入主题或完成核心玩法；无法解释其主题作用的元素应删除。
2. 主题适合时优先使用摄影与真实材质，追求全幅、电影感、细腻光线和可触摸的质感；不适合摄影时可采用插画、3D、数据图形或程序生成视觉。
3. 首屏应在三秒内说明它是什么、用户要做什么、会发生什么。大多数项目优先采用强沉浸封面；若封面妨碍直接开始核心互动，则让玩法本身成为首屏。
4. 文案少而准确，只使用自然的 `en-US`。标题可以有编辑感，正文不承担装饰任务。
5. 摄影、插画、3D 与数据视觉都不能只是背景壁纸：构图、裁切、材质、色彩和动效必须回应当前状态。

## 排版

- 控件、正文与关键信息使用清晰易读的系统无衬线字体。
- 艺术花体或意大利斜体仅用于少量品牌词、引文或情绪节点，不用于正文、表单、长句与关键操作。
- 允许强烈的编辑式层级、非对称网格和大留白，但信息顺序必须清楚。
- 不通过大量胶囊、卡片、发光描边或渐变制造“设计感”。这些形式只有在主题需要时才使用。

## 声音

- 每个 miniapp 都必须有与主题相符的背景音乐；首次有效用户交互后才解锁播放。
- 默认有声，用户必须能一键静音，且静音偏好持久保存。
- 点击、选择、组合、成功、解锁与完成可有短音效，参考优秀消除类游戏的节奏和反馈密度，避免每次触碰都发声。
- 音乐方向可参考 R&B、摇滚与纯音乐，但必须重新解释为项目自己的氛围；不得把同一首通用背景音乐套用到所有项目。
- 音效不得阻塞互动，也不得绕过 iOS 自动播放规则。

## 明确避免

- 与主题无关的通用霓虹、玻璃拟态、随机渐变与装饰光球。
- 为展示技术而增加的页面、控制项或过度动效。
- 文字墙、教程墙、内部状态或工程术语暴露给用户。
- 仅有静态浏览、没有完成状态与退出/重来路径的体验。

项目自己的目标方向与整改差距只能写入该项目的 `DESIGN.md`。
